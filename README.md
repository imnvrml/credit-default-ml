Can we predict, from six months of billing and repayment history, which credit-card clients will
default next month, and what is the best way to deal with the fact that only 22 % of them do?

## Dataset

**Default of Credit Card Clients**: 30,000 clients of a Taiwanese bank, 23 features, binary target.

> Yeh, I.-C. (2009). *Default of Credit Card Clients* [Dataset]. UCI Machine Learning Repository.
> https://doi.org/10.24432/C55S3H. Licensed under CC BY 4.0.

The original `.xls` file was converted to CSV without any other changes and is included as
[`data/credit_default.csv`](data/credit_default.csv). No download is needed.

## How to run

Requires Python 3.10+ (tested with 3.12).

```bash
git clone <this-repo-url> && cd <repo>
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# re-run everything (≈5–10 min on a laptop); regenerates figures/ and results/
jupyter nbconvert --to notebook --execute --inplace credit_default_ml.ipynb
```

You can also open the notebook with `jupyter notebook` and choose **Kernel → Restart & Run All**.
All randomness is fixed with `SEED = 42`.

To rebuild the PDF report from its HTML source (any Chromium-based browser works):

```bash
google-chrome --headless --no-pdf-header-footer --print-to-pdf=report/report.pdf report/report.html
```

## Method in one paragraph

1. **Split:** stratified 70 / 15 / 15 train / validation / test.
2. **Preprocessing:** a signed log transform for the skewed money columns, standardisation, and
   one-hot encoding. All of it sits inside scikit-learn pipelines, so it is only ever fitted on
   training folds.
3. **Baselines:** a dummy classifier and a plain logistic regression.
4. **Models:** six tuned model families, each with 20-iteration randomized search and the same
   5-fold stratified CV. They are logistic regression (elastic net), k-NN, Gaussian Naive Bayes,
   decision tree, random forest and gradient boosting.
5. **Metrics:** the primary metric is PR-AUC. The operating threshold minimises an expected
   misclassification cost (a missed defaulter costs 5, a false alarm costs 1) and is chosen on the
   validation set.
6. **Analysis:** learning curves, permutation importance, logistic regression coefficients and an
   error analysis.
7. **Twist:** class weights, random over- and undersampling, SMOTE and threshold tuning are
   compared with imbalance-aware metrics, then tested on artificially more imbalanced data
   (1–10 % defaults).
8. **Test set:** used exactly once, at the end.
